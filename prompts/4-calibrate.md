# 4. Calibrate

This is where the files get good. It's the loop Buzz Usborne describes: build something real, see what's wrong, write down the rule that was missing, run it again. Paste this with all your habitat files attached (or with the habitat MCP server connected).

---

Using **only** what my attached design files say (DESIGN.md, tokens.md and the component files), design this screen: **[A REAL SCREEN YOU BUILD OFTEN, e.g. "the account settings page"]**.

Describe it component by component (or build it in code if you can), and for every choice, say which rule in my files you followed. Where the files didn't tell you what to do, say so explicitly instead of quietly choosing.

Then I'll tell you what's wrong. For each problem:
1. Work out which rule was missing or unclear.
2. Write it into the right place: a component's `antiPatterns` or `whenToUse`, or a section of `DESIGN.md`. Include the `because`.
3. Add a row to the calibration log in `DESIGN.md`: date, what you did, the rule we added.

Then build the screen again. We'll stop when my corrections are about taste rather than rules.
